## Development trust model

The server has file-level `allow_dev_releases`, Windows has a compile-time development flag, and Docker has a policy in the immutable application mount. Missing flags default to production. Development bundles have a distinct format and no signature. All modes retain hashes, expected filenames, payload bounds, targets and monotonic versions/sequences. The authenticated online offer binds the downloaded bundle hash; development trusts the online server for authenticity. No remote setting can downgrade a production verifier.

Agents and releases report separate `signed` and `dev-sha256` channels. Upload, offer and push enforce channel selection. Disabling development mode stops queued dev offers. Production signing refuses build metadata marked development. No secrets or release signing are required for development; ephemeral signing in regression tests solely exercises production rejection/acceptance rules.
